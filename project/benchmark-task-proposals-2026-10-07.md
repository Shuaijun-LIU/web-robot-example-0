本轮用户要求：详细记录已有设计，再提出 2–4 个适合后续转为 benchmark、训练模型的任务。这里推荐 3 个，不用相似的分拣换皮凑数量。现有 Demo1/Assembly1、Demo2、Demo3、Demo4 不因本提案而修改。

## 1. 选择依据与推荐结论

先按问题独立提出候选，再查本地资产和官方源代码，最后做一次非提案作者的 agent 反向审查。筛选标准在排序前确定：

1. **协作内容真实**：物理耦合、共享空间或先后依赖至少有一项；明确最少需要几臂，不把四臂出现当成四臂必需。
2. **能形成学习问题**：不同初始条件会改变正确动作，而非只更换背景；能获得观测、动作、结果与阶段监督。
3. **结果可自动检查**：真实抓取、插入、容纳、释放、避碰可检查，不只看末帧相似度。
4. **数据可迭代扩大**：少量人工示范/现有控制器能作为起点，随后可重规划、复验和采集恢复。
5. **资源可落地**：已有 benchmark 资产优先，视觉和碰撞应对应；几何源文件存在与已验证能抓取是两个状态。
6. **补充现有能力**：不重复蛋分拣、扫码装盘、固定位置托锅和既有锤子装配。

| 候选 | 场景内容 | 重点训练能力 | 角色配置 | 建议定位 |
|---|---|---|---|---|
| A：开柜取件与协同配套 | 打开抽屉/柜门，取指定物件，经交接送入配套区，最后关柜 | 关节物体操作、遮挡处理、长序列调度、共享空间避碰 | 单臂基线 → 双臂接力 → 两组双臂并行 | 最适合先建立采集—训练—验证闭环 |
| B：无固定夹具的扶持插装 | 一臂扶持/调整支架，另一臂对准插入；其他臂供件和转移成品 | 相对位姿、接触调整、伙伴动作配合、失败重试 | 双臂精细核心 → 四臂供料/卸料 | 最值得优先研究的精细协作任务 |
| C：板件/托盘越障接力 | 两臂搬运，逐手转交另一对机械臂，绕过障碍后放到目标区 | 闭链协调、支撑切换、交接时机、运动规划 | 单臂/双臂对照 → 四臂接力 | 最能展示与评测多臂运动协同 |

建议实际启动顺序 **A → B → C**：先用资产和关节定义较现成的 A 跑通数据闭环。若更看重精细接触研究，则优先 B。A 的演示已发布；B 的完整物理演示已在本地通过验收；C 尚未开始实现。

## 2. A：开柜取件与协同配套

### 场景与完整动作

中央是源资产抽屉/低柜，周边是两个配套区。先验证一个柜体一对手臂；四臂版本采用两个相向或错开的柜体入口，必须先检查四台固定 Panda 的可达域，不直接搬入完整厨房。

- Arm 1：操作第一组门/抽屉，暴露目标；取出后负责关闭或下一个柜格。
- Arm 2：取出第一组所需物件，必要时交接到目的区可达的手臂。
- Arm 3：操作第二组门/抽屉，或接收从第一侧无法直接送达的物件。
- Arm 4：取出第二组物件并完成配套；和 Arm 2 协调中央通道。

一轮任务：接收物件清单 → 判断目标柜格 → 抓把手并打开 → 确认足够开度 → 取目标/必要时移开遮挡物 → 直接放置或交接 → 校验配套完整 → 关闭柜体 → 松手撤离。

**不要求机械臂无意义地一直扶着门。** 已检查的 RoboCasa 抽屉只有滑动关节阻尼，没有已验证的自动回闭弹簧。能松手就松手；若以后选择真实自闭门资产，再将持门加入任务。单臂顺序完成是合法基线，四臂的优势应通过吞吐量、共享通道调度等实验体现。

### 资产依据与集成工作

- 本地 RoboCasa：`robocasa/models/assets/fixtures/cabinets/drawer.xml`、`cabinet_single.xml`，已有 slide/hinge 关节；柜门面板、把手、贴图也在资源目录中。要复用其 fixture 构建逻辑，单独复制基础 XML 不能自动得到完整装饰、把手和尺寸适配。
- 本地 RoboTwin：`assets/objects/036_cabinet/46653/mobility.urdf`、`envs/put_object_cabinet.py`，已有一臂拉开、另一臂放入的任务参考。该柜体的原始数据授权须单独核查，不能仅凭 RoboTwin 总体资产卡推定第三方资产可随仓库发布；首选已有明确来源记录的 RoboCasa 路线。
- 物件先复用已引入的茶盒/咖啡盒，再扩展 RoboTwin 小盒、订书机、玩具等真实资源。新实例仍需逐项检查尺寸、碰撞和许可。

官方依据：[RoboCasa 原子任务](https://robocasa.ai/docs/build/html/tasks/atomic_tasks.html) 包含柜门/抽屉操作及柜内外取放；[RoboTwin Put Object Cabinet](https://robotwin-platform.github.io/doc/tasks/put_object_cabinet.html) 提供双臂柜体操作参考。这里借用资产和任务结构，不把它们直接宣称为现有四臂版本。

### 训练分布与评测

- 随机化：开度、目标物件位置/朝向、可见遮挡、订单内容、可达侧、共享区域请求顺序；后续才加不同柜体实例。
- 模型必须根据当前开度判断能否伸入，根据同伴位置决定等待/改道，根据目标物件而非固定坐标选择抓取。
- 成功：所有正确物件位于指定容器并受支撑，无错件/漏件，柜体回到目标关闭范围，夹爪退出；开关门成功与配套成功分别报告。
- 安全：门板扫掠区域与另一臂/物体的碰撞，夹爪被夹住，取错、掉落、死锁、超时。
- 数据价值：每个开柜、取件、交接都是可复用技能段；整体任务还能训练长序列调度。

首个可行性检查：在同样的一批布局、同样物件数下比较单臂串行、双臂、四臂。若单臂也能稳定完成，保留这一事实，把研究目标放在调度与效率上，不强行添加“必须扶门”的规则。

## 3. B：无固定夹具的扶持插装

### 场景与完整动作

中央为未固定的支架/安装座和匹配插装件；一个臂调整和稳定承接件，另一个臂观察相对姿态、对准并插入。先做有明确开口、无螺纹的刚性插装，不同时引入电缆、螺纹或柔性卡扣。

- Arm 1：抓持/稳定安装座，必要时调整角度；不是把安装座焊到末端。
- Arm 2：抓取匹配插装件，接近、对齐、插入；受阻时减小推进、退回再对齐。
- Arm 3：从零件区取下一件，准备下一套；不得伸入正在插装的空间。
- Arm 4：待装配稳定后转移成品，清空工位。

一轮任务：识别匹配件 → 扶持承接件 → 抓插装件 → 估计双方相对位姿 → 接近孔口 → 接触对准 → 插到目标深度 → 确认稳定 → 插装臂放手撤离 → 扶持臂释放/交成品 → 下一件。

与 Assembly1 的区别：不是重复固定横梁路径和敲击，而是让孔位/承接件姿态变化，训练**相对于另一个正在被控制的物体**的闭环动作与受阻恢复。

### 资产依据与不能照搬的地方

- 本地 robosuite 已有 `StandWithMount`、`HookFrame` 及 `ToolHang`，包含安装座腔体、插入杆和相关功能点。它们是 benchmark 原有的参数化模型，不是已找到高保真工业连接器；可以先用于几何/训练验证。若要做工业级展示，下一步另找经授权的连接器/支架模型，尚不能声称已具备。
- 源文件：`robosuite/models/objects/composite/{stand_with_mount,hook_frame}.py`、`robosuite/environments/manipulation/tool_hang.py`。
- [官方 ToolHang 代码](https://github.com/ARISE-Initiative/robosuite/blob/master/robosuite/environments/manipulation/tool_hang.py) 可作为部件与装配流程参考；这是对现有模型的复用，而非重新凭空设计工具。
- [TwoArmPegInHole 源码](https://github.com/ARISE-Initiative/robosuite/blob/master/robosuite/environments/manipulation/two_arm_peg_in_hole.py) 将孔板和插杆直接接到机器人末端 body，绕过抓取；只参考相对位姿关系，不复用此连接方式。
- 本地 ToolHang 配置里安装座 density=50000、框架 density=500。其重底座可能抑制扶持价值，不能原样继承后宣称证明双臂协作。新任务质量/惯量需按可信材料或实物依据设定并记录，不能为了让单臂失败而故意乱调。

### 训练分布与评测

- 随机化：承接件 XY/偏航/小倾角、插装件朝向、孔口尺寸与配合间隙、伙伴小幅位姿误差；从较宽配合开始逐步收紧。
- 观测：物件相对姿态、腕部图像和本体状态；接触/力信息可作为明确标注的额外传感器轨道，不偷偷输入像素轨道。
- 成功：插入深度达标、轴向/横向对齐、释放后稳定保持；几何必须有真实腔体，不允许穿过实体碰撞面。
- 质量指标：承接件漂移、接触力/冲量、卡住次数、退回重试次数、插入耗时、释放后滑出。
- 不采用“物体靠近孔就吸附”或“位姿误差小即判装配完成”。成功需要实际支撑与保持。

首个可行性检查：比较桌面支撑单臂、真实双臂扶持、理想固定夹具参考。允许合理借助桌面；若桌面方案同样稳，就筛选确有移动/倾覆问题的物件组合，或把它作为简单级别保留。理想固定夹具是条件更优的参考，不冒充严格数学上界，也不混入主要训练演示。

## 4. C：板件/托盘越障接力与支撑切换

### 场景与完整动作

工作区两侧有起点与目的区，中间有源资产货架/挡块形成的受限通道。两臂持物，另外两臂依次接手，从一个可达区域转移到另一个。先用无载板件，成功后再引入真实松散载荷。

- Arms 1/2：选择彼此不干扰的抓持区，共同抬起并调整长轴朝向。
- Arm 3：先接一侧，确认真实承载后允许原持有臂之一释放。
- Arm 4：接另一侧，剩余原持有臂确认接触切换后释放。
- Arms 3/4：协同转向/越障，将物件放到终点支撑物，再安全释放。

任务不是四只手挤到同一点。需要可容纳交接的分离抓持区，并校验手指、手腕、物体和障碍的完整扫掠体。可放下再抓的布局允许放下再抓，不通过无物理理由的“禁止落台”规则强造合作。

### 资产依据与集成工作

- 本地 RoboTwin `104_board`：已找到实例 0–4 的 `model_data*.json`、`visual/base*.glb`、`collision/base*.glb`；这是板件候选，不代表已证明其尺寸和抓持点适合四臂。
- 已引入 `008_tray` 可作为备选，但 Demo3 对其边沿夹起曾出现倾翻，**不能因为推移成功就假设承载搬运也成立**。若可用边沿/把手不足，换已有双把手资产，而非添加隐形握持点。
- 参考 [robosuite 双臂任务](https://robosuite.ai/docs/modules/environments.html) 中的 lifting、handover、transport 结构；其中 Transport 本身是容器间运送与清空目标容器，不是已实现本文的四臂板件越障。

### 训练分布与评测

- 随机化：起终点、物体朝向、障碍间距/高度、握持点、接收臂起始姿态、伙伴到达时间；载荷加入后再随机化其位置和总质量。
- 学习内容：双方相对 TCP 运动、物体姿态稳定、何时等待伙伴、何时允许释放、被阻挡后的换路线/换手。
- 成功：物体最终受支撑、无掉落、所有接触安全释放；载荷版本还要求内容物保留。
- 质量指标：倾角轨迹、滑移、失去有效支撑时长、交接次数、障碍接触、完成时间。不能只检查开始/结束两帧。
- 碰撞通道要允许合理的上方绕行，并实测它是否更好；若希望研究狭窄通道，应选有真实顶部边界的货架环境，不能偷偷用评价规则禁止抬高。

首个可行性检查：测源尺寸、质心、可达域和抓持区；对比单臂、双臂搬运、逐手接力，再运行两臂供方到两臂收方的版本。若单手即可稳搬，归类为接力/调度任务，不因没有双手必要性就否定整个方向。

## 6. 共同 benchmark 与训练设计

以下全部是后续实施规格建议，当前没有声称数据集已采完、策略已训练或 benchmark 已发布。

### 6.1 三种层次分开

1. **Oracle / 可行性分析**：使用特权物体状态和规划器确认任务可解，测协作相对单臂/固定调度的价值。它是数据生成起点，不要求它直接成为视觉策略。
2. **学习方法**：从采集的示范、失败与恢复中学习状态或图像条件动作；先验证受控分布内的模型。
3. **泛化与部署**：扩大对象、布局、角色和扰动分布，做留出测试；最后才考虑实机迁移。需要更多数据不是方法失败的证据。

先建立统一 native MuJoCo 环境适配与记录器，Web 继续负责演示、人工摆姿、轨迹检查及 episode 回放。四臂任务接口与引擎版本应一致；这不是自动恢复旧 line3 工程。

### 6.2 输入、动作与时钟

- 基础环境接口：`reset(seed, task_config)`、`step(action)`、`get_observation()`、`get_metrics()`、`export_episode()`。
- 建议策略频率 20 Hz，物理步长保持 2 ms，即每个策略周期 25 个物理步；渲染频率不驱动任务时钟。该数值是提议，不是本次代码变更。
- 第一版动作使用 `4 × (7 joint targets + 1 gripper width target)`，宽度统一为米；通过明确的适配器转换为实际 actuator 命令。记录高层目标与 bias feedforward 后的实际 `ctrl`，两者不可混淆。
- 后续提供 TCP 增量轨道：世界系或机器人基座系必须固定声明，统一 IK、速度/力限制；坐标系和夹爪单位写入 episode 元数据。
- 全局 RGB + 四个腕部 RGB 是建议配置；深度和额外接触/力反馈作为显式可选轨道。仿真 RGB-D 不等于已模拟真实 D435/D455 的噪声与成像误差。
- 原始对象状态/接触用于标注和 state-policy；纯 RGB 策略不得读取对象 ID、真值位姿、成功判据内部变量或专家阶段指令。
- 语言可用物件清单和目标条件表达，但先把状态/视觉闭环跑通；没有语言语义变化时，不强行冠以 VLA 任务。

### 6.3 每个 episode 要存什么

| 分组 | 必需字段 |
|---|---|
| 可复现元数据 | episode/seed/task ID、任务参数、asset IDs/hash、场景/控制器版本、引擎版本、源示范 family ID、随机化配置 |
| 同步观测 | 仿真时间戳、各相机帧与内外参、q/qvel、实际夹爪宽度、TCP 位姿；图片与动作时间对齐关系 |
| 动作 | policy 输入对应的高层目标、执行时刻、实际 ctrl、动作保持周期、IK/限幅结果 |
| 特权标注 | 对象位姿/速度、真实接触对与法向力/冲量、支撑/抓持关系、容器/插入/关节状态；与策略输入分开存 |
| 事件 | 阶段起止、角色交换、等待/让行、失抓、卡住、碰撞、恢复、终止原因 |
| 结果 | 各子任务成功、整任务成功、对象释放后状态、违规类型、耗时 |
| 回放快照 | 初始完整物理状态及必要控制器状态；明确跨引擎版本不保证逐位一致 |

保持成功轨迹和失败轨迹均可追溯；不要删掉失败以抬高数据生成成功率。安全保护若介入、动作被截断或由脚本替代，必须记录，不能把保护层的成功全部归功于策略。

### 6.4 示范扩展与失败恢复

- 少量人工末端关键姿态可以确定抓取、对接与退让意图；它们不是密集训练数据。需要补齐中间路径、执行完整物理过程并同步记录。
- 可借鉴 [MimicGen 的 object-centric subtask 数据生成接口](https://mimicgen.github.io/docs/modules/overview.html)：按对象坐标变换示范段，在新初始条件下实际重放并验收。
- 双臂同时持物、插装或交接的段落不能独立平移各臂轨迹；应以共同操作物/相对位姿建立耦合段，统一对齐并复验。参考 [DexMimicGen（ICRA 2025）](https://dexmimicgen.github.io/) 的双臂示范扩展方向，但不宣称它已有可直接接到本项目的四臂适配器。
- 保留顺序独立段与同步耦合段的依赖图。例如：两臂均确认接触才能搬运、接收方承载后供方才能释放。
- 每种任务采集“正确完成”以及“小偏差→退出/重抓/重新对齐→恢复”两类 episode。扰动施加时机、幅度及原因写入记录，不让物体为配合夹爪自动逃走或靠近。

### 6.5 基线与公平比较

1. 固定 waypoint 回放：检验随机化是否真的要求闭环，是易失效参照，不是主要学习方法。
2. 状态反馈启发式 + 固定优先级共享区调度：有当前状态，区别于纯回放。
3. 特权状态规划/重规划器：作为示范源和较强参考，不称为严格最优上界。
4. 状态输入 BC：先证明监督/动作定义有效。
5. 视觉时序 BC：可选 action chunking 或 diffusion policy；不在数据未就绪时同时堆叠复杂模型。
6. 多臂比较：联合策略、各臂独立策略、带伙伴状态/通信的策略；明确观察信息与计算预算，避免“信息更多”被误当方法效果。

单臂/双臂/四臂比较必须使用一致物件数、成功条件和墙钟/仿真时间口径。分别报告机械臂数带来的硬件资源差异，不把四臂完成四倍工作量直接当成算法优越性。

### 6.6 数据划分与评测

- 初期划分受控训练/验证/测试 seed；从同一源示范扩展出的 episode 以 family 分组，不把相邻帧或近重复轨迹分到不同集合。
- 分开测试：布局留出、对象实例留出、角色分配留出、伙伴速度/延迟、质量/摩擦受控变化。先单因素，后组合，不一开始就要求全组合泛化。
- 主指标为物理有效的整任务成功率，附子阶段成功率、失败类型、成功耗时及失败耗时。完成必须保持到释放后的观察窗口，不以“碰到目标”代替完成。
- 安全独立报告：非预期接触次数/持续时间/力或冲量、掉落、明显穿透、夹爪/部件卡住；求解器 penetration 一个数不能涵盖所有安全问题。
- 同步耦合段加相对位姿/滑移；A 加订单正确与关柜；B 加插入深度和释放保持；C 加倾角/载荷保留与支撑切换。
- 容差和接触阈值先依据几何、物理标定制定，再冻结测试配置，不能看到测试失败才持续放宽。若阈值只在单个接触采样瞬间抖动，应修正持续判定逻辑并保留原始证据。
- 发布按测试 seed 的原始结果与置信区间，学习实验至少多个训练 seed；未测前不写预测成功率。

### 6.7 建议的最小实验阶梯

以下数量是预算起点，不是达标承诺：

1. 每个候选先做 10–20 个几何/布局变体的可行性试跑，覆盖正确抓取、释放、最大伸展和易碰撞时刻；先筛掉不可达/网格问题。
2. 选择 1 个任务，先采约 50 条小分布示范和一组有标注失败/恢复，训练最简单状态 BC。记录生成尝试总数，不仅记录成功条数。
3. 若结果不佳，区分任务/数据/控制三个原因：任务过于脚本化看不出差距，就增加相关变化或换子任务；恢复样本不足就补监督；控制/碰撞错误先修环境。
4. 按学习曲线增加至 200/500 等规模，再接视觉模型；不把“50 条不足以泛化”当成研究方向不可行。
5. 最后增加另外两任务和跨布局/角色测试，形成一个共享接口、多种协作机制的 benchmark。任务选择权与新实施批准仍由用户掌握。

## 7. 反向审查与取舍记录

使用 scientific-brainstorming 的候选比较和非提案作者审查流程；一名独立 agent 只读检查源码并挑战捷径。本记录不是人类专家组共识，也不是实际学习实验结论。

| 审查问题 | 采纳的调整 |
|---|---|
| 抽屉打开后可能不需要扶持，单臂也能完成 | A 定位为关节操作与共享调度；保留单臂顺序基线，不伪造自闭弹簧 |
| ToolHang 重底座/桌面支撑会消除扶持价值 | B 先校准物理参数，测桌面基线，筛选确有支撑价值的实例 |
| TwoArmPegInHole 将工件直接固定于末端 | 只借相对姿态指标；实现时使用自由刚体与真实夹持 |
| 木板未必需要双臂，障碍可被抬高绕过 | C 先测握持/可达域，保留单臂和合理绕行，不人为增重或禁落台 |
| 四臂可能只增加吞吐而不增加必要性 | 每项分别报告物理核心所需臂数与四臂工作流收益 |

其他候选的处理：

- 订单分拣/混合装箱：可作为 Demo2/3 的语言与任务组合扩展，暂不单列新场景。
- 托盘负载平衡：并入 C 的进阶层，避免与 Demo4 托锅重复。
- 布料折叠、线缆穿孔、旋盖/螺纹装配：有学习价值，但本轮未核实满足要求的柔性/螺纹物理与可发布资产，保留为后续资源调查，不挤占前三项的首版数据闭环。

本次检索覆盖已用 benchmark 的官方任务、官方源代码和本地资源，不是全领域综述；没有据此声称任务组合具有论文新颖性。当前目标是建立可训练、可复现、能区分协作能力的任务族。
