# Franka Demo2 egg-sorting assets

This package is separate from the accepted Assembly1 / Demo1 assets. It includes the single-egg transfer, post-placement regrasp/reseat trial, and a four-arm sorting motion for all 16 eggs. The four-arm motion passes native, browser-WASM and actual-page physical replay, including carrying-state Reset; see `docs/progress/2026-09-09-demo2-four-arm.md` for measured acceptance results.

## Sources

- Panda: [MuJoCo Menagerie / Franka Emika Panda](https://github.com/google-deepmind/mujoco_menagerie/tree/main/franka_emika_panda). Source mesh files are copied unchanged. License: `licenses/Panda.txt`.
- Long-finger end effector: [MuJoCo Menagerie / UMI gripper](https://github.com/google-deepmind/mujoco_menagerie/tree/main/umi_gripper), originally from the [UMI hardware design](https://umi-gripper.github.io/). Original base, holders, fingers and GoPro meshes are preserved. License: `licenses/UMI.txt` (MIT).
- Egg shell and four-cavity insert: RoboDojo `Rigid/egg/00000` and the bottom of `Articulation/egg_holder/00000`, from the [RoboDojo asset dataset](https://huggingface.co/datasets/RoboDojo-Benchmark/RoboDojo), which declares Apache-2.0. Both local source hashes match the published dataset files. See `licenses/SOURCE-AUDIT.md` and `licenses/RoboDojo-assets-Apache-2.0.txt`; transformations are recorded below and in `manifest.json`.

## Adaptations and limits

- The egg is a converted existing visual mesh, rigidly centered. Ivory, brown, pale-green and cream are appearance classes derived from that mesh, with uniform size factors and documented material colors; these are not four independently sourced/verified bird species.
- Egg masses are scene assumptions of 45–60 g rather than the source metadata's 300 g. No shell-fracture or validated deformable-finger model is claimed.
- The original open egg-holder bottom is converted at X/Y scale 1.4 and Z scale 0.65. Source inserts receive another 0.6 Z factor to expose the egg's middle for the long fingers. The lid is omitted. Matte materials are visual/contact approximations, not deformable padding.
- Destination holders reuse the same four pockets, cut at the source divider lines. Each pocket is scaled by 0.35 in X/Y and 0.6 in Z around its measured hole center, then spaced at 84 mm pitch on its mat. This reduces the original oversized holes to support the egg's lower end while retaining clearance between neighboring eggs and the tilted fingers. These are source-derived modular holders, not unchanged benchmark geometry.
- Source inserts use 127 convex collision pieces. Output pieces are clipped from those same convex parts and transformed exactly like the visible pocket meshes. Collision geometry is hidden in group 3; holes are not replaced by solid box colliders.
- The complete sourced UMI handheld assembly is connected rigidly at the Panda wrist in simulation. This is an adaptation for inspecting reach and clearances, not an engineering-approved physical Panda–WSG adapter. The source finger geometry is not stretched. Closing coordinates are remapped so `0` closes and `255` opens the 100 mm nominal jaw stroke; actual pad gap depends on finger shape. Maximum actuator force is 12 N for this static prototype, not a validated safe egg-grasp force.
- The rectangular table/platform, box perimeter and tray mats are simple scene fixtures, not claims of imported benchmark models.
- Egg poses are generated by 200 seconds of passive gravity/contact settling offline, then saved as initial scene/Reset conditions. During interaction all eggs remain free bodies with contacts; there is no object pose animation, weld, magnet or attachment controller.
- Demo2 alone explicitly enables multi-point convex contact and 10 no-slip postprocessing iterations. These are MuJoCo contact-solver options, not object attachments. The older browser engine otherwise showed progressive tangential slip despite a maintained pinch. See [MuJoCo: preventing slip](https://mujoco.readthedocs.io/en/3.3.5/modeling.html#preventing-slip). Assembly1 / Demo1 and the shared engine dependency are unchanged.

## Rebuilding

CPU dependencies: Python, `usd-core`, `numpy`, `trimesh`, `coacd`, `mujoco`, `scipy`, `shapely`, `networkx`.

Run `scripts/build-egg-sorting-assets.py` from the repository root with `--menagerie` pointing to the source Menagerie checkout and `--robodojo` pointing to the RoboDojo checkout. The default output is this directory. The collision decomposition is cached in `insert-collisions.json` and invalidated automatically when converted geometry or decomposition settings change.

Inspect `manifest.json` for source hashes, dimensions, category assignments, mass settings and passive settling drift. Single-egg motion is exported by `scripts/solve-egg-transfer.py --export`. Four-arm `sorting-motion.json` is exported by `scripts/solve-egg-sorting.py --replay --arms 4 --input <checked-plan> --export` only after fresh fixed-path physical acceptance. The controller drives joint/gripper actuators and checks real contacts; object poses are never animated by these motion assets.
