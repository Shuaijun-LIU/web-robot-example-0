# XLeRobot Kitting 与 SO101 Gearbox 空间扩建设计

**日期：** 2026-08-13  
**状态：** 已获用户授权，设计完成后直接实施

## 目标

在不改变现有 XLeRobot Kitting 任务工作区、不改变 SO101 Gearbox 中央四臂、桌面、零件和任务站位的前提下，把两个场景扩展为完整且可检查的室内空间：

- XLeRobot Kitting 从单面后墙扩展为北、东、西三面墙，增加墙面细节和一个沿新墙放置的独立柜。
- SO101 Gearbox 扩大外围空间，加入沙发、电视、书桌和双屏，并从本地已有资源引入 Unitree G1 与 Go2+机械臂。
- 新增物体初始状态不得发生明显穿模；场景仍可在浏览器和 GitHub Pages 中加载。

## 不变范围

SO101 Gearbox 下列内容保持原值，不因房间扩建而移动或缩放：

- 四台 SO101 的基座位置：`(0, 0.42)`、`(0.42, 0)`、`(0, -0.42)`、`(-0.42, 0)`，基座高度 `0.8 m`。
- 中央桌面尺寸、桌腿位置、工装夹具、下壳体、轴、垫圈、齿轮、上盖和压装销。
- 24 维 SO101 `homeJoints`、四个控制目标、IK 和键鼠控制逻辑。

XLeRobot Kitting 的两台机器人、中央配货台、可抓取物、厨房后排、水槽、灶台、餐桌、果蔬、垃圾桶和储物架保持现有任务关系。

## 方案比较

### 方案 A：程序化几何近似机器人

用 box、capsule 和 cylinder 拼出 G1 与机器狗。优点是资产很小、接入简单；缺点是辨识度和展示质量不足，不能满足“从已有例子引入机器人”的要求。

### 方案 B：完整动态机器人模型

原样接入 G1 与 Go2+Arm，包括自由基座、关节、碰撞体和执行器。优点是后续运动能力保留完整；缺点是会把新增机器人的执行器插入当前 SO101 控制序列，增加自由落体、姿态失稳、自碰撞和控制串扰风险。本轮只要求建设场景，不值得引入这部分复杂度。

### 方案 C：高保真静态模型（采用）

复用现有真实网格和关节零位姿态，制作展示专用静态 MJCF：

- G1 来源：`google-deepmind__mujoco_menagerie/unitree_g1`。
- Go2+Arm 来源：`workspace/14.unilab/code/src/unilab/assets/robots/go2_arm`，其四足底盘网格复用同目录的 `go2/assets`。
- 删除新增机器人的自由关节、可动关节和执行器；隐藏其碰撞代理，只保留视觉网格。
- 通过 MuJoCo `<model>` 与 `<attach>` 挂入 SO101 场景，并使用独立前缀，避免命名冲突。

该方案保留外观质量，不改变 SO101 的执行器数量和控制索引，也不会让新增机器人自行跌落或产生初始碰撞。XML 和资产目录仍保留明确边界，后续可单独新增动态版本，而无需改动本轮静态展示模型。

## XLeRobot Kitting 空间设计

### 房间边界与视角

- 沿用北侧后墙，新增西侧墙和东侧墙，形成三面围合；南侧保持开放，作为机器人移动入口和默认观察方向。
- 侧墙内表面不越过当前地板边缘；墙体从地面起始，高度与后墙一致。
- 默认相机移动到南侧居中位置，避免东侧墙遮挡原先从东南方向观察的视线。

### 墙面细节

- 西墙：一扇大窗，包含窗框、横竖分隔、玻璃面和窗台。玻璃与装饰件关闭碰撞。
- 东墙：两幅低饱和度挂画，包含外框、内衬和画面板；所有装饰件与墙面保留微小间隙，避免共面闪烁和几何重叠。

### 独立柜

- 沿东侧新墙靠北放置一个独立高柜，面向房间内部。
- 柜体与墙面留出可见但很小的安装间隙；柜门、抽屉、把手和踢脚板均在柜体外表面，不与柜体中心体积交叉。
- 柜子不进入两台移动机器人围绕中央配货台的主要通道。

## SO101 Gearbox 房间设计

### 房间与中央保护区

- 地板扩展到约 `9.2 × 7.2 m`，新增北、东、西三面墙，南侧开放供观察。
- 以中央工位为圆心保留至少 `1.4 m` 半径的无新增家具区；原四臂、桌面和任务物体保持原坐标。
- 新家具与机器人均放置在中央保护区外，并保留环形通道。

### 功能分区

- 西侧客厅区：三座沙发、电视矮柜、电视屏幕、地毯、边几和落地灯。沙发与电视相向，且不侵入中央保护区。
- 东北工作区：书桌、桌腿、双显示器、键盘、台灯和办公椅。屏幕朝向房间内部。
- 北侧展示区：G1 站立模型，朝向南侧和中央区域，脚底与地板齐平。
- 东南展示区：Go2+Arm 站立模型，机械臂朝向中央但与 SO101 工位保持充分距离。
- 墙面增加少量画框/吸音板，维持生活空间质感，但避免高亮、荧光配色。

## 资产与加载架构

SO101 Gearbox 改用独立本地资产根目录 `public/assets/so101-gearbox-room/`：

- 复制原 SO101 场景所需 XML 与网格，使 GitHub Pages 不依赖第三方 raw URL。
- `robots/g1/` 保存 G1 静态模型及实际引用网格。
- `robots/go2_arm/` 保存 Go2+Arm 静态模型、机械臂网格与四足底盘网格。
- 保留第三方许可证和来源说明，仓库文档不写入本机路径或账号信息。

XLeRobot Kitting 仍使用现有远程 XLeRobot 资产，只通过当前 XML patch 增加房间结构。

## 物理和视觉约束

- 房间、家具和装饰是固定 body；可抓取物维持既有 freejoint。
- G1 与 Go2+Arm 是静态视觉模型，不提供本轮控制入口，不参与接触求解。
- 固定家具不得与地板产生超过 `5 mm` 的初始穿透；新增机器人外观不得穿过地板、墙面或家具。
- 侧墙、相机和家具布局必须让中央工作区及新增机器人在默认截图中可辨认。
- 不增加 weld、magnet、自动吸附或 proximity attachment。

## 验证标准

1. 单元测试确认两套场景的新增房间边界、分区元数据、关键物体名和中央工位不变。
2. SO101 Gearbox 编译后仍恰好有 24 个执行器，并能解析四个 `r*_Base` 和 `r*_tcp`。
3. G1 与 Go2+Arm 的静态根 body 均存在，且新增模型不带 freejoint 和 actuator。
4. 两套 MJCF 的严格初始接触检查均无超过 `5 mm` 的穿透；目标是零负距离穿透接触。
5. TypeScript、完整测试和生产构建通过。
6. 刷新 `so101-gearbox.png` 与 `xlerobot-kitting.png`，人工检查墙面、家具、机器人尺度、方向、间距和遮挡。
