# Assembly1 第一步四臂协作就位设计

日期：2026-08-13

## 目标与范围

本轮只实现 `Franka Assembly1` 的第一步动作：四个 Panda 同时从当前姿态移动到各自任务的预抓取位。此步骤不闭合夹爪、不抬起工具、不移动框架或横梁，也不继续执行后续装配。

第一步的意义是先独立验证四臂运动控制、角色分工、可达空间和无碰撞就位。只有这一层稳定后，后续步骤才增加真实接触和抓取。

## 四臂角色与目标

| 机械臂 | 场景位置 | 第一步职责 | 高位路点（m） | 最终预抓取位（m） |
|---|---|---|---|---|
| Arm 1 / `r0` | 南侧 | 框架南侧夹持位 | `[0.00, -0.36, 0.50]` | `[0.00, -0.31, 0.34]` |
| Arm 2 / `r1` | 东侧 | 电动扭矩工具 | `[0.53, -0.42, 0.50]` | `[0.53, -0.42, 0.36]` |
| Arm 3 / `r2` | 北侧 | 待安装横梁北端 | `[-0.49, 0.65, 0.50]` | `[-0.49, 0.65, 0.34]` |
| Arm 4 / `r3` | 西侧 | 框架西侧夹持位 | `[-0.48, 0.00, 0.50]` | `[-0.46, 0.00, 0.34]` |

这些位置均为 TCP 世界坐标。初版让南侧臂跨到东南工具区、北侧臂跨到横梁中段；真实 IK 验证表明两者在保持末端方向时会越过关节限位。因此最终分工按最近工作区调整：东侧臂负责东南工具，北侧臂抓横梁靠北端，南/西两臂负责框架稳定。第一步保持各 TCP 的 home 方向，只改变位置；夹爪保持完全张开。机械臂在本步只到达物体外侧上方，下一步再做末端对齐、下降和真实夹持。

## 动作轨迹

- 总时长 `3.0 s`，使用 MuJoCo 仿真时间。
- 第 `0–1.5 s`：四臂使用 smoothstep 关节插值，从当前控制目标移动到高位路点。
- 第 `1.5–3.0 s`：从高位路点下降到最终预抓取位。
- 全部 8 个关节路点由 `scripts/solve-assembly-step1-waypoints.mjs` 使用同一 Panda MJCF、同一 `solveSelectedIk` 和相同末端方向离线求解，并在写入场景前检查关节限位与 TCP 位置误差。
- 页面运行时解析全部四组 namespaced site/joint，并原子检查 8 组预求解关节值；任一资源缺失或关节越界时整步不启动，避免部分机械臂单独运动。
- 不在按钮点击后对包含四臂及全部自由物体的完整场景执行有限差分 IK；该做法实测会长时间阻塞 Web 主线程。点击后只执行已验证的真实关节控制轨迹。
- 运行时只写四组手臂 actuator control，不写 `qpos`，不修改工具或框架自由关节。
- 四个 gripper actuator 始终写入打开值 `255`。

## 控制与人工交互

- 左上角性能面板下方增加独立小面板，仅在 `Franka Assembly1` 显示。
- 初始按钮文字：`执行第一步：协作就位`。
- 状态依次为：`就绪`、`执行中`、`第一步完成` 或 `规划失败`。
- 执行中按钮禁用；完成后保持禁用，用户使用现有 Reset 恢复场景后才能重新执行。
- 开始执行时关闭当前选中机械臂的 IK 写入，防止它与四臂轨迹竞争。
- 完成后同步当前 gizmo 到新的 TCP 位姿，但不自动继续运动；键盘和 gizmo 手动控制恢复可用。
- Reset 立即取消未完成轨迹、恢复 MuJoCo home state，并将第一步状态恢复为 `就绪`。

## 软件边界

- `src/assemblyStep1.js`：角色、TCP 路点、离线求解的关节路点、时间段和纯插值函数，不依赖 React。
- `src/AssemblyStep1Controller.tsx`：解析并验证四组 namespaced 资源、仿真步进和状态回调。
- `src/AssemblyStep1Panel.tsx`：左上角按钮和状态显示。
- `src/App.tsx`：只负责 Assembly1 条件显示、运行请求、Reset 和当前 IK 协调。
- `scripts/solve-assembly-step1-waypoints.mjs`：可重复生成并核对关节路点、限位和 TCP 误差。
- `scripts/verify-assembly-step1.mjs`：浏览器真实场景验收。

## 失败处理

- 场景未 ready、站点/关节/actuator 缺失或预求解路点越过当前模型关节限位时，状态改为 `规划失败`，控制量保持原值。
- 场景切换或 Reset 会取消进行中的动作，旧回调不能继续写入新场景。
- 本步不提供暂停后续跑或自动重试，以避免状态复杂化。

## 验收标准

- 按钮只在 Assembly1 显示且位于左上角性能面板下方。
- 点击一次后四个 Panda actuator block 都发生明显变化，动作在约 3 秒仿真时间后结束。
- 四个 TCP 的最终位置分别落在上述目标 `3 cm` 以内。
- 三件工具、框架、横梁和紧固件在动作前后没有被脚本修改位置。
- 夹爪全程打开；没有 proximity attach、weld、磁吸或物体跟随。
- Reset 能取消/清除第一步状态，原有 18 个手动控制目标仍通过回归测试。
